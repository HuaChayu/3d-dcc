# 数据层架构规矩

> 适用范围：路径追踪视口、离屏出图、以及未来任何新的渲染模式。
> 本文件是数据层的"宪法"。新增功能前先读这一页，再动手。
> 代码落点：`3d渲染/数据层/`（域 基础 / 四个 域 / 对象 关节 / 场景 快照 / 架构 约束）。

---

## 1. 分层图

```
                       ┌──────────────────────────────┐
                       │        场景数据层（唯一真源）        │
                       │  几何域 · 材质域 · 灯光域 · 变换域   │
                       │           对象关节表              │
                       └──────────────┬───────────────┘
                                      │  生成快照（只给只读视图，零拷贝）
                                      ▼
                       ┌──────────────────────────────┐
                       │      场景快照（不可变）             │
                       │  几何版本 · 材质版本 · 灯光版本      │
                       │  变换版本 · 对象版本               │
                       └──────────────┬───────────────┘
                                      │  消费者只能读，不能写
                                      ▼
        ┌─────────────────┬─────────────────┬─────────────────┐
        │  路径追踪视口      │    离屏出图       │  未来的其它模式    │
        │ （仅读快照）       │  （仅读快照）      │  （仅读快照）      │
        └─────────────────┘ └─────────────────┘ └─────────────────┘
```

依赖方向是**单向向下**：数据层不知道渲染器存在，快照不知道消费者存在。
阶段 1 之前那种"渲染器里自己攒一份几何签名 / 自己判哪个字段变了"的做法，属于历史包袱，
后续接入时逐段替换为"读快照 + 比版本号"。

## 2. 每个概念的唯一所有者

| 概念 | 唯一所有者 | 物理位置 | 其它地方允许做什么 |
|---|---|---|---|
| 几何（形状枚举、包围盒、几何生命周期） | 几何域 | `四个 域.swift` | 只能通过 `稳定标识<几何域标签>` 引用 |
| 程序网格形状 | `MeshKind`（场景 数据模型.swift） | 既有文件 | 只可读，不许再定义第二份形状枚举 |
| 导入网格实体数据 | `导入网格库` + `导入网格` | 工具函数/导入导出 | 几何记录只存 UUID |
| 材质参数、节点图 | `MaterialAsset`（材质 数据模型.swift） | 既有文件 | 材质记录只存 `UUID`，不复制参数 |
| 材质槽 / 逐三角形 / 图集切片映射 | 对象关节（`材质分配`） | `对象 关节.swift` | 只可读 |
| 灯光参数（功率、色温、半径、锥角…） | `灯光设置`（场景 数据模型.swift） | 既有文件 | 灯光记录持有它，不另立默认值 |
| 灯光实例与生命周期 | 灯光域 | `四个 域.swift` | 只可通过 id 引用 |
| 本地矩阵、父子层级、世界矩阵 | 变换域 | `四个 域.swift` | 世界矩阵只能问域要，不许别处自算 |
| 实例关系（几何id/材质分配/变换id/灯光id） | 对象关节 | `对象 关节.swift` | 只可读 |
| 版本号、脏标记、引用计数、回收队列 | 各域自身 | `域 基础.swift` | 消费端只读版本号，不许自己维护"是否要重建"的标志 |

**不属于任何域的东西**（别硬塞）：

- GPU 缓冲、BLAS/IAS、加速结构 → 归渲染器，数据层不碰
- 相机、采样数、分辨率、曝光 → 归渲染设置，不是场景数据
- 瞬态 UI 状态（选中、悬停、拖拽中的草稿矩阵）→ 归 UI，**只有提交后才写回变换域**
- 文件路径、编码、序列化格式 → 归导入导出层

## 3. 关系约束（谁连谁，几比几）

| 关系 | 基数 | 由谁保证 |
|---|---|---|
| 几何 ↔ 对象 | 1 : N（一份几何可被多实例引用） | 几何域不记对象；对象持几何 id |
| 材质 ↔ 对象 | M : N | `材质分配` 三种形态 |
| 对象 ↔ 变换 | **1 : 1** | `对象关节表.变换占用` 反向表 + `检测关系` |
| 对象 ↔ 灯光 | **1 : 1** | `对象关节表.灯光占用` 反向表 + `检测关系` |
| 灯 ↔ 几何 | **0 : N**（灯不产几何、不进几何域） | `检测关系` 拒绝"既是几何又是灯" |

## 4. 允许与禁止的依赖

| 行为 | 结论 |
|---|---|
| 渲染模式读快照 | ✅ 允许，且是唯一合法入口 |
| 域 → 域通过稳定 id 互相引用 | ✅ 允许（只存 id，不存对方记录） |
| 对象关节表一次读多个域做只读校验 | ✅ 允许（它是设计上的 M:N 连接者，且只读） |
| 域引用渲染器 / `PT*` 类型 / Metal | ❌ 禁止（数据层不知道渲染器存在） |
| 渲染模式写域 | ❌ 禁止（只能读快照；写入必须走 UI/编辑层的所有者令牌） |
| 跨域直接调用对方的方法改数据 | ❌ 禁止（拿不到别人的令牌，代码层面已封死） |
| 用一个 Int 下标长期指代记录 | ❌ 禁止（槽位会复用，必须用 `稳定标识`） |
| 消费者自己缓存"哪部分要重建" | ❌ 禁止（比版本号即可） |
| 出现异常就重建 / 重试 / 自动恢复 | ❌ 禁止（断言 + 日志，Debug 当场炸） |

## 5. 七条规矩 → 代码落点

| # | 规矩 | 落点 |
|---|---|---|
| 1 | 唯一所有者 | `所有者令牌` + 每次写入的 `预检写入`；`所有权登记表.登记(概念:令牌:)` 拒绝同概念第二所有者；`架构违规.重复所有者` |
| 2 | 单向依赖 | 数据层不 import 渲染器；写 API 全部要求令牌（跨域写拿不到令牌）；快照只暴露 `域只读视图`，类型上没有写入口 |
| 3 | 禁止容错重建 | `架构记录` / `架构断言`：Debug `assertionFailure`，Release 打 stderr；所有非法访问只 `return nil/false`，**不补建、不改版本号**（自检里专门验证"非法访问后版本号与记录数不变"） |
| 4 | 稳定 id | `稳定标识<域>{槽位, 代际}`，域用空枚举做类型级隔离；`释放槽` 时代际 `&+ 1`；`检测标识` 把"槽空 / 代际不符 / 越界"统一判为 `.下标作引用`；域对外不提供任何 Int 下标读 API |
| 5 | 引用计数 + 延迟回收 | `增引用` / `减引用` / `请求删除`（仍有引用 → 进 `待回收`，不释放）/ `轮询回收(令牌:GPU仍在使用:)`（引用归零且 GPU 说不用了才真删）；删除后不允许再被引用 |
| 6 | 变换链拒绝成环 | `变换域.检测成环`（逐级上溯 + 步数上限）→ `设父` 中 `架构记录(.成环)` 并返回 `域违规`；`世界矩阵` 求解同样有步数上限，成环返回 nil |
| 7 | 派生零拷贝 | `域只读视图<域,元素>` / `变换视图` / `对象视图` 只持有源域引用，不复制记录；`场景快照` 只存六个视图 + 五个版本号；`快照.是否过期(相对:)` 供消费者比对 |

自检入口：`数据层自检() -> [String]`（返回空数组即全部通过）。它只调"检测"层，不会触发断言把 App 打断。

## 6. 稳定 id 与回收机制设计

**标识结构**：`稳定标识<域>(槽位: Int, 代际: UInt32)`

- `槽位`：数组下标，只在域内部临时使用
- `代际`：槽位每次被释放 +1，复用时新记录带新代际
- 因此"旧 id"永远指向不到"后来复用同一槽位的新记录"——这就是不用 UUID 也能稳定引用、
  且能挡住"下标当引用"的原因。域标签把它绑死在某个域上，跨域混用编译期即报错。
- 需要在日志/统计里压成一个数字时用 `压缩值`（不参与语义判断）。

**粒度选择：数组 + 空闲槽栈，不做紧凑化**

- 遍历是每帧热路径，数组内存连续，无哈希开销（字典每帧遍历要跳桶）
- 紧凑化会让已有 id 的槽位漂移，等于破坏稳定 id；空槽代价只是数组里一个 nil
- 单条取用 O(1)：直接下标 + 一次代际校验
- 删除密集时靠 `空闲槽` 复用，槽表不会无限膨胀
- 遍历性能保证：`遍历` / `脏标识` / `全部标识` 都是单次线性扫描；`遍历` 完全零分配

**回收三段式**：`请求删除` →（有引用则挂 `待回收`）→ `轮询回收`（引用==0 且 GPU 不再使用）→ 真删 + 代际+1 + 槽位入空闲表。

## 7. 新增功能时该往哪加（检查清单）

动手前逐条打勾，任何一条打不上就先改设计：

1. [ ] 这个数据属于几何 / 材质 / 灯光 / 变换里的哪一个？→ 加进对应域的记录
2. [ ] 它是不是"实例关系"（谁引用谁、几比几）？→ 加进 `对象 关节`
3. [ ] 它是不是渲染器的工作状态（缓冲、AS、累积）？→ **不许进数据层**
4. [ ] 它是不是编辑器的瞬态状态（拖拽中、选中中）？→ **不许进数据层**，提交时写域
5. [ ] 我有没有定义第二份形状枚举 / 第二份默认值 / 第二份校验？→ 有就是错，改读既有定义
6. [ ] 新概念有没有在 `所有权登记表` 登记？没登记就不算有主人
7. [ ] 写入口有没有要求 `所有者令牌`？没有就是漏洞
8. [ ] 引用别人是用 `稳定标识` 还是 Int 下标？用下标就是错
9. [ ] 消费者是读快照还是自己去翻域？必须读快照
10. [ ] 代码里有没有"检测到异常就重建/重试/兜底"？有就删掉，改成断言 + 日志
11. [ ] 新增关系是 1:1 吗？是的话有没有加反向占用表
12. [ ] 需不需要新版本号？复用现成的四个（+对象），别造第五个"总版本"

**禁止清单（全是阶段 1 踩过的坑的直接来源）**

- ❌ 在渲染器里再算一遍"几何签名 / 灯签名"来决定重建 ← 版本号存在的意义就是消灭它
- ❌ 拖拽中途直接把草稿值写进域 ← 每帧一次版本号翻动，会把"只在拖灯"变成"全量重建"
- ❌ 用一个布尔 `需要重建` 标志代替版本比对 ← 无法区分"几何变 / 只变换变"
- ❌ 灯位置混进几何签名 ← 灯不产几何，几何段一旦含灯位，拖灯必然触发几何重建

## 8. 稳定性证明（本轮改动前后渲染结果一致）

本轮只新增 `3d渲染/数据层/` 下的文件，**没有任何既有文件被修改**，也**没有任何既有调用点**引用数据层：

1. 数据层是纯新增目录：`域 基础.swift`、`四个 域.swift`、`对象 关节.swift`、`场景 快照.swift`、`架构 约束.swift`、本文件。
2. 全工程没有任何 `场景数据层` / `场景快照` 的实例化点（唯一的实例化出现在 `数据层自检()` 里，而自检当前也没有被任何启动路径调用）。
3. 因此 PT 渲染器、PT 着色器、视口、出图、场景构建的执行路径与改动前相同：没有新代码进入任何一帧的调用栈。
4. 编译验证：`xcodebuild -scheme 3d渲染 -configuration Debug build` → **BUILD SUCCEEDED**。
5. 行为验证方式（手工，30 秒）：打开 App 拖灯 / 拖物体 / 改材质，观感与改动前一致；自愈门（`PT 渲染器.swift:107`）保留未动。
6. 可复核命令：`grep -rn "场景数据层" 3d渲染 --include=*.swift` 应只命中 `数据层/` 目录内部。

## 9. 下一步接入顺序建议（阶段 2 后续，不在本轮范围）

**先灯，后几何，最后材质/变换细化。** 理由：灯是当前 bug 焦点（拖灯触发重建），
且灯的数据量最小，改动面最可控。

1. **建影子读取**：让灯光消费端（场景转译 的灯收集）先按快照读灯，但**仍然走原来的重建路径**，
   只把"灯记录从哪来"换掉。此时渲染结果必须逐帧一致（同样的灯、同样的顺序、同样的参数）。
   验证：同一场景保存出图 PNG，改动前后做逐像素比对，必须完全一致。
2. **版本号接管判定**：把"灯变了没有"由签名比对改为 `快照.版本.灯光` 比对，
   保留原有 `只改灯位 → 原地刷新` 分支逻辑不变，只换输入。验证同上（逐像素），
   外加拖灯帧日志必须出现 `blas=reuse ias=reuse`。
3. **其它域同法接入**：几何 → 变换 → 材质。每接一个域都跑一次逐像素比对，不通过就回滚该域。
4. **空屏问题单独处理**：`isPaused=true` 的空场景暂停 + 自愈门日志属于渲染器侧改动，
   在数据层接入完成后单独一轮做，不与接入混在一起，避免两个变量同时动导致无法归因。

**接入铁律**：一次只接一个域；每接一个都做"渲染结果零变化"验证；验证不通过不许往下接。

## 10. 几何域的引用计数与"字段退役"（本阶段已落地）

**定位**：`SceneObject` 只做壳 —— id / 名字 / 变换 / 材质引用 / 可见性 / 引用祖先。
几何本体（顶点）永远不进模型；模型上只留"指向哪块几何"的定位信息。

1. **写入口唯一**：`mesh` / `导入网格ID` / `导入符号` 已改为 `private(set)`，
   外部只能调 `SceneObject.设置几何来源(程序形状:导入网格:导入符号:)`。
   任何"直接改字段"的写法都会被编译器挡掉 —— 写权限就是这条约束的执行者。
2. **读入口唯一**：消费端只经 `几何接线.共享.程序形状(键:兜底:)`；
   全工程已无 `?? object.mesh` 形态的散落兜底。兜底只作防御（取不到域才用），
   命中会累加到 `兜底命中次数`，正常应为 0。
3. **同步不再滞后**：`布局 状态.objects` 的 `didSet` 里立刻把几何来源推给域，
   所以拖拽、新增、删除、导入之后，域都与模型同拍，不依赖视口帧时机。
4. **引用计数**：`几何接线` 维护 `导入网格 → 引用它的几何记录数`（`网格引用数`，
   查询用 `引用数(网格:)`）。这本账是"域知道自己指着谁"的唯一依据。
5. **两阶段回收**：某块导入网格"连续两轮轮询都没人引用"才 `几何接线.共享.移除`。
   轮询 0.5s 节流；`objects` 为空的那一轮直接跳过 —— 项目加载是"先清空再填"，
   一轮就删会把整池抹平。
6. **过渡态保护**：切换项目整段流程 `几何接线.共享.暂停回收(true/false)` 包住，
   整池替换 + Store 重新载入之间引用关系不可信，禁止回收。
7. **序列化读域**：`生成快照()` 前用 `按几何域回填` 把几何来源对齐到域再落盘。
   域里查不到的物体原样保留；域退化成"程序网格"时不覆盖已有的导入网格引用
   （那通常意味着那一刻网格池取不到，不代表几何真的变了）。
8. **网格池是域的私有存储**：`导入网格库` 的入口已从 `shared` 改名为 `域内部`，
   全工程 31 处 `.shared` 直连（15 个文件）已清零，一律改走
   `几何接线.共享.存入/取/存在/版本号/移除/恢复/保留/快照/快照与版本/
   全部标识/占用条目数/总三角形数/局部包围球/生成实体/转PT片段/三角点列`。
   池**不合并**进域（值语义会复制、共享会破、增量落盘会废、故障域会合并），
   但"谁能摸到池"由编译期强制为只有域 —— 逻辑唯一性靠访问权限执行，不靠自觉。
   判据：`grep "导入网格库.域内部"` 应只在 `几何接线.swift` 内出现。
